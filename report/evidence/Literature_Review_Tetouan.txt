Literature Review of Machine-Learning-Based
Power Consumption Forecasting in Tetouan City
Machine Learning Project Literature Analysis
1
Introduction
Electricity-demand forecasting is an important component of modern energy-management systems.
Accurate forecasts can support generation planning, load balancing, resource allocation, demand
management, and efficient electricity distribution.
This literature review focuses on studies using the Power Consumption of Tetouan City dataset.
Since the present project is conducted in the context of a Machine Learning course, conventional
machine-learning studies are treated as the primary sources for algorithm selection and model devel-
opment.
Studies based on deep learning, statistical forecasting, or other specialized time-series models are
included only when they provide useful methodological ideas related to:
• data preprocessing,
• target construction,
• temporal feature engineering,
• lag construction,
• train–validation–test splitting,
• time-series cross-validation,
• leakage prevention,
• scaling,
• hyperparameter optimization,
• realistic forecasting evaluation.
Therefore, the objective of this review is not only to identify which algorithms have previously been
applied, but also to understand how different studies process the data, construct their features, divide
the time series, train their models, and evaluate forecasting performance.
2
Dataset
The Power Consumption of Tetouan City dataset contains electricity-consumption measurements
collected from three electricity distribution networks in Tetouan, Morocco.
The three electricity-consumption zones are:
• Zone 1: Quads,
• Zone 2: Smir,
• Zone 3: Boussafou.

Key Insights and Implications
The literature shows a clear evolution in the use of the Tetouan City dataset.
Earlier work, particularly P1, mainly focused on conventional regression algorithms such as Linear
Regression, Decision Tree, Random Forest, and Support Vector Regression.
Later studies gradually introduced:
• more sophisticated feature engineering,
• historical electricity-demand features,
• systematic hyperparameter optimization,
• improved temporal validation,
• more recent ensemble-learning methods such as XGBoost.
An important implication for the current project is that a meaningful contribution does not neces-
sarily require a deep-learning model.
Instead, conventional ML algorithms can be retained while improving the overall experimental
methodology through:
better features + temporal validation + systematic tuning.
The continued appearance of the Tetouan dataset in recent journal publications also indicates that
the dataset remains useful for benchmarking electricity-demand forecasting methodologies.

Key Insights and Implications
Tree-based models appear consistently important throughout the literature.
Random Forest was the strongest model in the original benchmark, while later studies continued to
include:
Decision Trees,
Random Forest,
XGBoost.
Another important observation is that model performance depends not only on the algorithm.
The surrounding pipeline also matters:
Model + Features + Validation + Tuning.
Therefore, the current project does not need to compare a very large number of algorithms.
A compact but representative model set is more appropriate:
LR →DT →RF →SV R →XGBoost
where:
• Linear Regression provides a simple baseline,
• Decision Tree represents a basic nonlinear model,
• Random Forest provides an ensemble-tree baseline,
• SVR represents kernel-based nonlinear regression,
• XGBoost provides a modern boosted-tree model.
This allows the project to focus more strongly on methodology and feature engineering rather than
simply increasing the number of algorithms.

Key Insights and Implications
The preprocessing comparison shows a clear development in feature engineering.
The original study mainly follows:
Weather + Calendar →Prediction.
Later studies increasingly follow:
Weather + Calendar + Historical Consumption →Prediction.
This is important because electricity demand is strongly dependent on its recent and periodic his-
torical behaviour.
P5 demonstrates the usefulness of even simple lag variables:
yt−1,
yt−2,
yt−3.
However, these cover only 30 minutes of historical demand.
Because the Tetouan dataset is sampled every 10 minutes, the current project can construct more
meaningful multi-scale features:
yt−1
(10 minutes),
yt−6
(1 hour),
yt−144
(1 day),
yt−1008
(1 week).
This creates a promising extension:
Weather + Calendar + Short-term Lag + Daily Lag + Weekly Lag
The literature also suggests that scaling should be model dependent.
For example:
• SVR is highly sensitive to feature scales,
• Linear Regression may benefit from standardized features,
• Random Forest generally does not require feature scaling,
• XGBoost generally does not require feature scaling.
Therefore, preprocessing should ideally be placed inside model-specific pipelines rather than applying
exactly the same scaling transformation to every model.

Key Insights and Implications
The reviewed studies show that hyperparameter optimization can substantially affect forecasting
performance.
P1 demonstrates that even conventional models such as Random Forest, Decision Tree, and SVR
benefit from systematic hyperparameter search. P2 further shows that different search strategies can
produce different results for the same underlying model.
However, conventional shuffled cross-validation is potentially problematic for time-series forecasting.
Even when the final test set is chronological, information leakage can occur during model selec-
tion if future observations are included in validation folds used to tune a model trained on earlier
observations.
17


--- PDF PAGE 18 ---
Therefore, the current project should combine hyperparameter optimization with a time-series-aware
validation method.
A suitable approach is:
GridSearchCV + TimeSeriesSplit
or:
RandomizedSearchCV + TimeSeriesSplit
Randomized Search may be preferable for Random Forest and XGBoost when the hyperparameter
space becomes large.
Most importantly, the final test period should remain completely untouched during:
• feature selection,
• preprocessing selection,
• scaler selection,
• hyperparameter optimization,
• model selection.
Only after the entire modelling pipeline has been selected should the final model be evaluated on the
holdout period.

Key Insights and Implications
The reported results should not be compared as if they represented a single benchmark leaderboard.
For example, P5 predicts Zone 3, whereas other studies may use an aggregated target based on all
three electricity zones.
Therefore:
RMSEZone 3
cannot be directly compared with:
RMSEsum of Zones 1–3.
The literature nevertheless suggests two important patterns.
First, more recent studies increasingly use historical electricity consumption as an input variable.
Second, strong classical ML models remain competitive when combined with appropriate feature
engineering.
Therefore, all models in the current project should be evaluated under exactly the same experimental
conditions:
• same target,
• same input features,
• same training period,
• same validation period,
• same final test period,
• same forecasting horizon,
• same evaluation metrics.
The recommended common metrics are:
RMSE,
MAE,
MAPE,
R2
The objective should therefore be a fair within-project comparison, rather than claiming superiority
over numerical values obtained under different experimental settings in previous studies.

The literature demonstrates a gradual shift from purely exogenous forecasting toward autoregressive
machine learning.
The original structure is approximately:
Weather + Calendar →Power Forecast.
A stronger modern design is:
Weather + Calendar + Historical Power →Power Forecast.

Identified Research Gaps
Based on the reviewed studies, several methodological gaps can be identified.
13.1
Unclear Temporal Validation in Earlier ML Studies
Some conventional ML studies report percentage-based splitting without clearly specifying whether
observations are kept in chronological order.
This creates the possibility of temporal data leakage.
A better structure is:
Past Training Data →Validation →Future Test Data.
13.2
Limited Historical Demand Features
The original ML benchmark does not explicitly use strong autoregressive electricity-demand features.
P5 introduces:
yt−1,
yt−2,
yt−3,
but these describe only 30 minutes of historical demand.
Longer periodic patterns remain available for exploration.
13.3
Inconsistent Target Definitions
Different studies predict:
• individual zones,
• Zone 3 only,
• the sum of all three zones,
• the mean of all three zones.
Therefore, direct numerical comparison across papers is difficult.
The current project should select a single primary target before model comparison.

13.4
Limited Explainability
Many papers primarily emphasize predictive accuracy.
Additional interpretation methods could help determine whether forecasting performance is mainly
driven by:
• previous consumption,
• hour of day,
• weekday,
• temperature,
• humidity,
• diffuse radiation.
Potential methods include:
• Random-Forest feature importance,
• permutation importance,
• SHAP.

Recommended Research Questions
A suitable main research question is:
How effectively can conventional machine-learning algorithms forecast short-term elec-
tricity consumption in Tetouan City when meteorological, calendar, and multi-scale his-

A secondary research question is:
To what extent do historical lag features representing short-term, daily, and weekly

Which conventional machine-learning model provides the best trade-off between predic-

demand forecasting?

Conclusion
The reviewed literature demonstrates that the Tetouan City dataset has been used with a broad
range of electricity-demand forecasting methods.
The original study establishes conventional ML baselines and identifies Random Forest as a strong
model.
Later studies introduce:
• more systematic model optimization,
• lagged electricity-demand features,
• fuzzy feature enrichment,
31


--- PDF PAGE 32 ---
• XGBoost,
• more rigorous chronological evaluation.
However, several limitations remain.
Earlier ML studies do not always clearly document temporal splitting, while later studies using strong
chronological evaluation often rely on deep-learning or specialized forecasting architectures.
The current project can therefore combine complementary ideas from different studies:
Conventional ML + Multi-Scale Historical Features + Chronological Validation + Time-Series-Aware Tuning
This approach remains fully appropriate for a Machine Learning course while addressing method-
ological limitations identified in the previous literature.
